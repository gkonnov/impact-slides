# Impact Slides

Практическая база подготовки, доработки и ревью презентаций для менеджмента в IT и технологическом бизнесе. Помогает объяснять сложное, обучать команды, обосновывать решения и продавать ценность с фокусом на клиентскую задачу и бизнес-результат.

Версия: 0.3.0 · Дата: 2026-10-15 · Репозиторий: `gkonnov/impact-slides`.

## Как начать

1. Определите задачу, аудиторию и формат: подготовить новый материал, доработать существующий или провести ревью.
2. Откройте [workflow.md](workflow.md): там порядок работы и готовый запрос для ИИ.
3. Используйте [общие правила](slides/common.md) и только подходящие дополнения из таблицы ниже. Для работы с ИИ также подключите [AGENTS.md](AGENTS.md).

| Задача презентации | Дополнение к общим правилам |
|---|---|
| Помочь клиенту оценить предложение и следующий шаг | [client.md](slides/client.md) |
| Выбрать направление или объяснить стратегический курс | [strategy.md](slides/strategy.md) |
| Обучить, объяснить экспертную позицию, согласовать работу | Пока общие правила; отдельные профили добавляются при появлении специфических требований |
| Смешанная задача | Только применимые части профилей, без двойного учёта замечаний |

В базе 14 правил: семь общих, четыре клиентских, три стратегических. Тип определяется задачей, а аудитория и формат задаются отдельно; не нужно применять все правила к каждой презентации.

## Структура

```text
impact-slides/
├── README.md                 # Что это, быстрый старт, как добавить своё
├── AGENTS.md                 # Инструкция для ИИ
├── workflow.md               # Подготовка, доработка и ревью
├── slides/
│   ├── common.md             # Общие правила
│   ├── strategy.md           # Стратегия и управленческие решения
│   └── client.md             # Клиентские и продающие презентации
├── .gitignore
└── LICENSE
```

В корне описано, как работать с базой; в `slides/` находятся только правила и особенности задач. Примеры встроены в правила, историю хранит Git; отдельные папки промптов, архивов и пустых профилей не нужны.

## Использование с ИИ

Приложите разрешённые к обработке материалы и заполните короткий запрос. Подробный бриф и варианты результата находятся в [workflow.md](workflow.md).

```text
Работай с презентацией по Impact Slides:
https://github.com/gkonnov/impact-slides

Прочитай README.md, AGENTS.md, workflow.md, slides/common.md
и подходящий профиль из навигации README.

Задача: [подготовить / доработать / проверить].
Аудитория: [...]. Цель: [...]. Формат: [...].
Результат: [структура / текст слайдов / ревью / файл с указанием формата].
Ограничения и разрешённые изменения: [...].
Укажи прочитанные файлы и версию правил.
```

База подходит для Computer и других ИИ, но не является автоматически установленной глобальной настройкой. Если GitHub недоступен, передайте Markdown-файлы вместе с материалом; наличие `AGENTS.md` само по себе не доказывает его загрузку.

## Как добавить своё

- **Правило**: сначала проверьте, нет ли его в `common.md` или нужном профиле. Уточните существующее, если проблема та же; не копируйте общее правило в несколько файлов.
- **Новый вид**: добавьте один файл в `slides/` и строку в навигацию выше. Например, `learning.md` или `expert.md`, но только с содержательными дополнениями для отдельной задачи, не с пустой заглушкой.
- **Карточка**: стабильный ID, короткое правило, понятная проверка, искусственный пример и границы применения. Для нового профиля выберите свой префикс, например `LEARNING-001`; существующие ID и удалённые номера не переиспользуйте.
- **Обсуждение**: предложите конкретную правку через pull request. Если пока есть только проблема, начните с issue; опишите, где правило помогает и когда не должно применяться, без закрытых подробностей.
- **Перед включением**: проверьте отсутствие дублей, работоспособность ссылок и сохранение удачных решений разных форматов. Изменения принимает владелец или назначенный сопровождающий; версия обновляется при смысловом изменении.

Новый профиль содержит только отличия от общего ядра. Личные предпочтения по фону, шрифту или переносам задаются брифом либо явно обозначаются как необязательные; они не становятся стандартом для всех коллег.

## Принципы базы

Сначала задача аудитории, логика и доказательства, затем текст и оформление. База не предписывает одинаковую композицию: вопрос, метафора, плотное приложение или финал без запроса на решение могут быть уместны.

При ревью различайте установленную ошибку, вопрос к недостающим данным и полезное улучшение. Важность определяется последствиями для аудитории; хороший референс не удостоверяет каждую цифру в нём, а редакционная формулировка не становится автоматически корпоративным стандартом.

## Версии и совместимость

Версия 0.3 переименовывает проект, сохраняет компактную структуру и расширяет процесс с ревью до подготовки и доработки. Содержательные правила и их ID сохранены; личные визуальные предпочтения больше не привязаны к одному владельцу в общем ядре.

В версии 0.2 было объединено 27 карточек в 14. Для старых замечаний: `COMMON-003` и `COMMON-015` перешли в `COMMON-002`; `COMMON-006` в `COMMON-005`; `COMMON-008` и `COMMON-009` в `COMMON-007`; `COMMON-010` и `COMMON-012` в `COMMON-011`; `COMMON-014` в [AGENTS.md](AGENTS.md). `CLIENT-002` и `CLIENT-004` покрываются `CLIENT-001` и `COMMON-007`; `CLIENT-006` вошёл в `CLIENT-005`; `STRATEGY-004`–`STRATEGY-006` в `STRATEGY-003`.

Для воспроизводимой работы фиксируйте commit SHA. Подробная история изменений остаётся в Git; старые пути файлов следует заменять путями из текущей структуры.

## Публичные правила, закрытые материалы

Здесь только общие правила и искусственные примеры. Не добавляйте реальные рабочие презентации, клиентские и персональные данные, внутренние показатели, частные ссылки, переписку и отчёты закрытого ревью, в том числе в issue или pull request.

Материалы для работы передаются отдельно в разрешённой среде. `.gitignore` снижает риск случайного добавления файлов, но не заменяет проверку содержимого и полномочий перед публикацией.
