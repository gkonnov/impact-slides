# Impact Slides

Правила подготовки, доработки и ревью презентаций и текстов для менеджеров в IT и бизнесе. Помогают объяснять сложное, обучать команды, обосновывать решения и продавать ценность. В центре внимания задача читателя и результат, а не оформление ради оформления.

## Быстрый старт

Передайте модели запрос и разрешённые к обработке материалы:

```text
Используй https://github.com/gkonnov/impact-slides.
Прочитай инструкции и подходящие правила, не только README.
Задача: [подготовить / доработать / проверить].
Материал и читатель: [...]. Цель: [...].
Результат и допустимые изменения: [...].
Назови версию правил, прочитанные файлы и границы проверки.
```

База не подключается к модели автоматически. Если GitHub недоступен, приложите Markdown-файлы; способы подключения и полные запросы есть в [examples.md](examples.md).

## Выбрать правила

Прочитайте [порядок работы](workflow.md), а при работе с ИИ также [инструкции](AGENTS.md). Для презентации возьмите [общие правила](slides/common.md) и дополнение по задаче:

| Задача презентации | Дополнение |
|---|---|
| Помочь клиенту оценить предложение | [client.md](slides/client.md) |
| Выбрать направление, обосновать ресурсы или объяснить курс | [strategy.md](slides/strategy.md) |
| Обучить, объяснить позицию, согласовать работу | Достаточно общих правил |
| Решить несколько задач | Применяйте дополнения только к соответствующим блокам |

Для текста возьмите [texts/common.md](texts/common.md), указанные там общие принципы и дополнение из таблицы жанров. Файлы жанров содержат только отличия; видение при необходимости подключает правила стратегии.

В базе 50 правил: 16 для презентаций (8 общих, 5 клиентских, 3 стратегических) и 34 для текстов (6 общих и 28 жанровых). Не применяйте все сразу: задача и стадия работы определяют нужный набор.

## Что где лежит

- **README.md**: назначение базы, выбор правил и участие.
- **AGENTS.md**: полномочия ИИ, безопасность и честность проверки.
- **workflow.md**: последовательность подготовки, редактуры и ревью.
- **examples.md**: запросы и подключение с GitHub или файлами.
- **slides/**: общие правила, стратегия и клиентское предложение.
- **texts/**: общие правила, эссе, записка, видение, статья, ответы и кейс.

Правила не становятся корпоративным стандартом автоматически. Требования площадки и согласованные предпочтения автора важнее рекомендуемой структуры, но не отменяют достоверность. Ошибку, вопрос к данным и необязательное улучшение различайте по [workflow.md](workflow.md).

## Развивать базу

- **Проверить необходимость**: единичная правка ещё не общее правило. Сначала найдите похожее требование и проверьте новую формулировку на разных задачах.
- **Описать правило**: понятное действие и способ проверки. Пример нужен для неоднозначности, исключение для реального риска неверного применения; не повторяйте их ради формы.
- **Сохранить структуру**: полное требование хранится в одном месте, в других допустимы короткое напоминание и ссылка. Новый жанр содержит только отличия; добавьте его в таблицу выбора, не создавайте пустые разделы.
- **Сохранить идентификаторы**: новый номер не должен совпадать с существующим. При объединении не переиспользуйте прежний номер и не перенумеровывайте всю базу; обновите ссылки и версию.
- **Согласовать**: сначала покажите изменения владельцу или сопровождающему. Внешний участник предлагает PR или issue без закрытых данных; прямой коммит возможен по разрешению владельца для согласованного набора.
- **Проверить**: ссылки, идентификаторы, счётчики, условия применения и сохранение смысла удалённых пунктов. Предпочтения по фону, шрифту и оформлению не превращайте в требования ко всем участникам.

## Не публиковать закрытые материалы

В публичной базе допустимы общие правила и придуманные примеры, но не рабочие презентации, клиентские и личные данные, внутренние показатели, частные ссылки, переписка и закрытые отчёты. Это относится и к issue, PR и логам.

Передавайте материалы для анализа отдельно в разрешённой среде. `.gitignore` не заменяет проверку содержания и прав на публикацию; подробные ограничения находятся в [AGENTS.md](AGENTS.md).
